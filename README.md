# DeskNest Studio

Online store for DeskNest Studio's digital productivity templates, built for **Cloudflare Pages**.
Live domain: **decoyclaw.com**

- Static site (HTML/CSS/JS, no framework) generated from `src/` into `dist/`
- Cloudflare Pages Functions for checkout, order lookup and secure downloads (`functions/`)
- Payments through Stripe Checkout (hosted payment page: no card data touches this site)
- Product files stored in a **private** R2 bucket and served only for paid, non-refunded orders
- Six real products with 21 downloadable files (US Letter PDFs, DOCX, XLSX, ZIP), generated by `products/generate.py`
- Prices in US dollars (USD), set in `src/data/catalog.json`

## How a purchase works

1. The customer adds products to the cart. The cart is kept in the browser's local storage.
2. On `/checkout/` they see the seller, every product and its price, and the one-time and digital-delivery terms. They tick two required boxes (Terms, and the request for immediate digital supply).
3. `POST /api/checkout` creates a Stripe Checkout Session. **Prices always come from `src/data/catalog.json` on the server**, not from the browser.
4. After payment, Stripe returns the customer to `/order/?session_id=…`. `GET /api/order` checks the session with Stripe and lists the files.
5. Each download, `GET /api/download`, re-checks the session (paid, not refunded, file belongs to a purchased product) and streams the file from R2.

## Repository layout

| Path | What it is |
|---|---|
| `src/data/site.json` | Business details: name, domain, email, phone, address, governing law. **Edit here.** |
| `src/data/catalog.json` | The six products and their prices (shared by the site and the checkout API) |
| `src/data/manifest.json` | Generated file list and checksums (written by `products/generate.py`) |
| `src/data/contents.json` | Page-by-page contents of each product (written by `scripts/product_contents.py`) |
| `src/site/*.mjs` | Page templates: home, shop, product pages, checkout, order, about, FAQ, contact, legal pages |
| `src/static/` | CSS, JS, fonts (self-hosted Inter, OFL), images, product previews |
| `functions/` | Pages Functions: `api/checkout`, `api/order`, `api/download`, www→apex redirect |
| `products/` | Template generator: page layouts (`content.py`), PDF/DOCX rendering, XLSX workbooks |
| `scripts/build.mjs` | Builds `dist/` |
| `scripts/upload_r2.py` | Uploads product files to the private R2 bucket |
| `scripts/deploy.mjs` | Creates or updates the Pages project, deploys, and connects the domain and DNS |
| `tests/` | End-to-end test (real Functions and local R2 against a mock Stripe API) |

## Before going live: things only the owner can provide

1. **Stripe secret key.** Checkout is disabled until it is set. Customers see "Online payment is not available at the moment".
   ```bash
   npx wrangler pages secret put STRIPE_SECRET_KEY --project-name worknest-studio
   ```
2. **Stripe Dashboard settings that must match the site.** The site states these, so set them exactly:
   - **Settings › Public details:** business name `DeskNest Studio`, website `https://decoyclaw.com`, support email `help@decoyclaw.com`, support phone `+1 417 398 2273`, support address (91-1009 Owakalena St, Kapolei, HI 96707), Terms of service URL `https://decoyclaw.com/terms/`, Privacy policy URL `https://decoyclaw.com/privacy/`.
   - **Statement descriptor:** `DESKNEST STUDIO`. The site tells customers the charge appears under that name (`statementDescriptor` in `src/data/site.json`).
   - **Settings › Checkout:** turn on *Contact information*, *Legal policies* and *Refund policy*. Choose "refunds" for digital goods, with a link to `https://decoyclaw.com/refunds/`.
   - Optional: after the Terms URL is set, change `STRIPE_TOS_CONSENT` to `"true"` in `wrangler.toml` so Stripe's page also shows a required terms checkbox.
3. **Sales tax.** Prices are in USD and exclude sales tax. If you need sales tax collected, enable Stripe Tax, then set `STRIPE_AUTOMATIC_TAX = "true"` in `wrangler.toml` and redeploy. Tax is then shown on the payment page before the customer pays, which is what the site's policies say.
4. **Support mailbox.** `help@decoyclaw.com` is shown throughout the site and in the product files, so make sure it receives mail. For example, use Cloudflare Email Routing (Email › Email Routing) to forward it to your inbox.
5. **Legal entity.** If DeskNest Studio is a trading name of a company or of you personally, put the legal name (and any registration number) in `src/data/site.json` (`legalName`, `registrationNumber`). The Terms, Privacy Policy and About page pick it up automatically. Governing law is set to the State of Hawaii, based on the business address. Have the policies reviewed for your situation.

## Deploy

The R2 bucket `worknest-studio-files` (an internal name customers never see) already holds the current product files.

**Option A: from your computer**
```bash
npm ci
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... node scripts/deploy.mjs
# optionally add STRIPE_SECRET_KEY=sk_live_... to store the key in the same run
```

**Option B: GitHub Actions.** Add repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` (and optionally `STRIPE_SECRET_KEY`), then run **Actions › Deploy to Cloudflare Pages › Run workflow**.

The script is safe to re-run. It:
- checks the token
- builds the site
- creates the `worknest-studio` Pages project if it is missing
- deploys to production
- attaches `decoyclaw.com` and `www.decoyclaw.com`
- creates proxied CNAME records to `worknest-studio.pages.dev`

It never overwrites existing DNS records; it tells you what to change instead. The domain must already be a zone in the same Cloudflare account. The token needs *Cloudflare Pages: Edit*, *Workers R2 Storage: Edit*, *DNS: Edit* and *Zone: Read*.

## Day-to-day operations

- **Re-send a download link.** In Stripe, open the payment (search by customer email, or by the order reference `DN-…` stored in the payment's metadata). Copy the Checkout Session ID (`cs_live_…`) and send the customer `https://decoyclaw.com/order/?session_id=<that id>`.
- **Refund.** Refund the payment in Stripe. The order's download links stop working automatically.
- **Change a price or text.** Edit `src/data/catalog.json` or `src/data/site.json`, then deploy.
- **Change a product file.** Edit `products/content.py` or `products/workbooks.py`, then run:
  ```bash
  pip install reportlab python-docx openpyxl pillow boto3   # once; pdftoppm (poppler-utils) is also needed
  python3 products/generate.py       # regenerates files, previews and src/data/manifest.json
  python3 scripts/product_contents.py   # page-by-page contents shown on product pages
  python3 scripts/brand_assets.py      # hero, card and sharing images
  R2_ACCESS_KEY_ID=... R2_SECRET_ACCESS_KEY=... CLOUDFLARE_ACCOUNT_ID=... python3 scripts/upload_r2.py
  node scripts/deploy.mjs
  ```
  Always upload after regenerating. The manifest's checksums must match what is in R2.

## Develop and test

```bash
npm ci
npm run build                 # writes dist/
npm test                      # end-to-end: checkout, payment, downloads, refunds (needs Playwright + Chromium)
npx wrangler pages dev        # local preview at http://localhost:8788 (checkout needs STRIPE_SECRET_KEY in .dev.vars)
```

Never commit API tokens, R2 keys or Stripe keys. `.dev.vars` and `.env` files are git-ignored.
